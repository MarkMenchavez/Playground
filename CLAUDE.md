### ⚙️ **Technology Stack & Architecture**
The project is a production-grade, cloud-native solution utilizing the .NET framework (currently targeting .NET 10). The overall architecture is designed around a service-oriented or modular monolith pattern, prioritizing resilience and scalability. Key design principles include:

*   **Event-Driven Communication:** Services are heavily decoupled using asynchronous messaging via a message queue (e.g., Rebus Bus/RabbitMQ). Core business logic involves publishing domain events that are consumed later by background processes.
*   **Dual Hosts:** The system is logically separated into two distinct, deployable hosts:
    1.  **API Host:** The synchronous entry point for external clients. It handles request routing and low-latency operations via an API Gateway pattern.
    2.  **Worker Host:** A dedicated background service responsible for long-running tasks (e.g., batch processing) and asynchronous event consumption, scaling independently of the primary HTTP interface.
*   **Observability:** All services are instrumented using OpenTelemetry for distributed tracing, centralized logging correlation, and metrics gathering, which is critical when debugging cross-service workflows.

*   **Clean/Restore Dependencies:**
    ```bash
    dotnet restore
    dotnet clean
    ```
*   **Build (Standard Release):** For creating deployable artifacts.
    ```bash
    dotnet build --configuration Release
    ```

*   **Run Tests:** The test suite structure includes separate components for Unit, Integration, and Benchmark testing located in `tests/`. For standard execution:
    ```bash
    dotnet test
    ```
*   **Run Application:** To run the primary API Host (assuming local setup):
    ```bash
    dotnet run --project <path_to_api.csproj>
    ```
